# 扩展点 / SDK 空间预留设计（ext-design）

性质：设计文档（概念纯净，无工具指向性）。机制依据与来源引用见 docs/survey-competitor-mechanisms.md（调研文档，含出处）。

## 0. 结论（先读）

1. **第一原则【已定，焊死】**：任何"自修改 / 自手术"类扩展动作——修改自身或宿主的代码、配置、提示词、规则——必须经既有裁决口（ApprovalPort）人审，用户同意才执行；**程序与智能体零自我批准权**。"智能体给自己做手术"允许存在，但手术同意权永远在人手里。
2. **扩展运行模型【已定】**：三步——声明（扩展登记将要动的面位与动作）→ 人审（命中既有 policy 审批往返，用户裁决）→ 执行。不为扩展另造安全机制，复用现有裁决口。
3. **本次交付 = 架构空间预留，不是完整插件系统**【已定】：只落扩展面清单、SDK 骨架、人审边界；扩展加载器、沙箱、热替换均属后续开发。
4. **立桩落点**【已定】：`src/ext/`（注册面 `mod.rs` / 钩子扩展位 `hooks.rs` / 权限与人审闸口 `permissions.rs`），可编译、带测试；尚未接线进主执行流。

## 1. 第一原则与安全边界

### 1.1 自修改的定义【已定】

自修改（自手术）= 扩展对"自身或宿主"四类资产的任何改动：

| 资产 | 含义 | 类型落点 |
|---|---|---|
| 代码 | 自身或宿主的实现代码 | `SelfModifyTarget::Code` |
| 配置 | 运行配置与环境约定 | `SelfModifyTarget::Config` |
| 提示词 | 系统提示、上下文冻结前缀 | `SelfModifyTarget::Prompt` |
| 规则 | 裁决规则表、纪律条款 | `SelfModifyTarget::Rules` |

### 1.2 人审触发线【已定】

| 动作 | 人审 | 理由 |
|---|---|---|
| 自修改（以上四类全部） | **一律是，无例外** | 第一原则 |
| 放松裁决（缩小拒绝面） | 是 | 实质是改规则，等同自修改 |
| 注册新工具（扩张能力面） | 是 | 能力扩张，须人拍板 |
| 收紧裁决（扩大拒绝面） | **否（可直接挂）** | 安全增强，只缩不放 |
| 纯观察（事件订阅 / 钩子回调） | 否 | 只读、零副作用 |
| 附录位追加上下文 | 否 | 只追加、全量留痕、不碰冻结前缀；越过附录位改冻结前缀即自修改 |

边界写法【已定】：审批策略扩展位**只许收紧、不许放松**——收紧属安全增强可直接挂载，不必逐次打扰用户；放松必须走人审。免人审不等于免留痕：全部扩展动作照常进事件证据链。

### 1.3 零自我批准权的落点【已定】

- 类型：`ExtAction`（动作枚举，`SelfModify(SelfModifyTarget)` 变体把自修改做成类型级标记）；
- 函数：`needs_human_approval(action) -> bool`（穷尽匹配，新增动作变体漏归类即编译不过）；`human_gate(action, ask)`（命中人审的动作必须经 `ask` 真人裁决往返，无人同意即拒绝）；
- 测试：`src/ext/permissions.rs` 逐一断言全部自修改目标命中人审、无人同意时闸口拒绝。

### 1.4 三步运行模型【已定】

```
扩展声明（ExtensionDecl 登记面位 + 动作）
    → 人审（needs_human_approval 判定 → 既有裁决往返 → 用户裁决）
        → 执行（钩子回调 / 注入 / 注册落地）
```

`ask` 的实现必须是真人裁决往返；程序与智能体不得代答、不得缓存历史同意、不得以自动批准端口替代此处人审——自动放行视同零批准。

## 2. 扩展面清单（手术刀下刀处）

| # | 扩展面位 | 语义 | 人审口径 | 状态 |
|---|---|---|---|---|
| 1 | 工具注册扩展位 | 为智能体新增工具面 | 注册前人审（能力扩张） | 面位已定，接线【待磨合】 |
| 2 | 生命周期钩子扩展位 | 挂接生命周期钩子收敛点（`event::hooks::emit_hook` 是既有唯一收敛点，硬约束 14），回调返回放行/转人审/阻断 | 回调只许收紧，免人审；返回转人审即走裁决往返 | 骨架已定，挂接【待磨合】 |
| 3 | 上下文注入扩展位 | 向上下文增量附录段（`context.rs` 附录位）追加条目 | 附录位内免人审；碰冻结前缀 = 自修改，人审 | 面位已定，接线【待磨合】 |

| 5 | 界面面板 / 命令注册位 | 注册界面面板或命令入口（斜杠命令属此位） | 注册免人审；命令触发的动作逐动作过闸口 | 【待磨合】 |

| 7 | 自修改动作位 | 改自身/宿主的代码、配置、提示词、规则 | **一律人审（第一原则）** | 已定 |

## 3. SDK 形态草案

### 3.1 扩展 = 声明 + 回调【骨架已定，语义待磨合】

- **声明式描述**：`ExtensionDecl { name, version, surfaces, actions }`——扩展自报家门：叫什么、申请哪些面位、将要做哪些动作（权限声明）。声明即三步模型的第一步，执行期逐动作过闸口。
- **回调函数**：钩子面回调签名 `Fn(&HookEvent) -> HookVerdict`（Send + Sync，约定零副作用）；需要改变任何东西时走动作位声明 + 人审，不在回调里偷偷动手。
- **注册面单入口**：`ExtensionRegistry`（声明增删查）+ `HookRegistry`（回调注册/注销/分发）。重名拒绝、禁止隐式覆盖；空注册表 = 未挂扩展，行为与无扩展时一致。
- **裁决三态**：`HookVerdict = 放行 / 转人审 / 阻断`，聚合取最严者（阻断 > 转人审 > 放行）。回调只能收紧，不能放行掉既有裁决。

### 3.2 事件流订阅【待磨合】

事件流订阅挂既有读侧回放口（EventSource，`event::source`），扩展以只读订阅者身份消费事件流；观察类扇出与决策链同步裁决分离（硬约束 14：同步只允许存在于决策链）。订阅的退订语义、异常隔离（单个订阅者出错不拖垮总线）在接线期收口。

### 3.3 代码骨架索引【已定】

| 文件 | 内容 |
|---|---|
| `src/ext/mod.rs` | `ExtSurface`（七个面位）、`ExtensionDecl`、`ExtensionRegistry`、`ExtError` |
| `src/ext/hooks.rs` | `HookEvent`、`HookCallback`、`HookVerdict`、`HookRegistry::dispatch`（挂收敛点的分发立桩） |
| `src/ext/permissions.rs` | `SelfModifyTarget`、`ExtAction`、`needs_human_approval`、`human_gate`（第一原则落点） |

## 4. 与核心四接口的关系【已定】

四个接口（决策 7）：EventSink / EventSource（事件层）、ApprovalPort（裁决往返）、ModelClient（模型客户端）。扩展挂接在四接口**外圈**，不改核心契约：

| 接口 | 扩展与它的关系 |
|---|---|
| EventSink（事件提交） | 扩展只经由宿主代为留痕，不直接拿提交口（防伪造证据链）【待磨合：扩展自有事件的落法】 |
| EventSource（事件回放） | 扩展只读订阅（§3.2），不写 |
| ApprovalPort（裁决往返） | **扩展人审的唯一通道**：自修改/放松/扩能力一律经此口问人；扩展无权自建裁决口 |
| ModelClient（模型客户端） | 扩展不直接接触（防绕过决策链直驱模型）；虚拟模型面后置【待磨合】 |

依赖方向【已定】：`ext` 只依赖 event 层类型（生命周期点位）与标准库，不依赖工具/策略/模型层；核心契约文件零改动（本次仅 `src/lib.rs` 增一行模块声明）。

## 5. 路线图

**0.3.x 落地（0.3.0 = 系统提示词落地 + 核心机制首件）**：

1. 扩展面位骨架与人审边界——本次已交（`src/ext/` 可编译带测试）；
2. 钩子分发挂接既有生命周期收敛点（扇出接线，观察类异步、决策链同步收紧）；
3. 上下文附录位接注入（附录位内追加、全量留痕）；
4. 人审口对接既有裁决往返（`human_gate` 的 `ask` 实现指向 ApprovalPort 阻塞往返）；
5. 审批策略收紧位挂载（收紧直接挂、放松走人审）。

**【待磨合】**：工具注册面的白名单/参数强类型口径；界面命令位的壳层对接；扩展加载与发现形态（外部描述文件还是进程内注册）；版本协商；钩子三态是否够用；扩展卸载语义。

**【待核验】**：观察类扇出的时延与吞吐影响（无实测数据）；扩展数量级上限（注册表线性扫描是否够用）。
