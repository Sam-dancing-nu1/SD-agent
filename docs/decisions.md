## 一、已定（8 项）

### D1 核心语言 = Rust 【已定】
- 结论：常驻 runtime、工具执行、状态机、事件流的实现语言定为 Rust。
- 依据：常驻进程开销最小、单文件分发、三平台成熟；TUI 与桌面壳同语言共享核心库（UI 调研 2.1）。
- **附加前提（拍板记录必须随行，防成死参）**：若实际开发中暴露出"无 Rust 能力且产品抢时间"的现实，允许转 Go 并整体切到备选组合（Go + bubbletea + 本地服务形态）；此前提是转档的唯一合法通道，转档需作者明示。

### D2 TUI 框架 = ratatui + crossterm 【已定】
- 结论：终端界面用 ratatui（画布+差分刷新），终端控制层用 crossterm（UNIX+Windows，最低 Windows 7）。
- 依据：随 D1 走；业界对照（Codex CLI 同路线，UI 调研 [S13] 实锤）。
- 附加条件：表格/弹窗/表单组件自研——工作量已在 UI 调研风险节写明，不另立预算惊喜。

### D3 桌面壳 = Tauri 2.x 【已定，2026-10-02 质询复核中】
- 结论：桌面端用 Tauri 2.x（系统 WebView 渲染 + Rust 外壳），三平台打包/签名/强制签名更新器配套官方齐（UI 调研 [S6][S7][S8] 均核到官方原文）。
- **作者质询（2026-10-02，待复拍）**：WebView 渲染被质疑"不是原生、寒酸"。原生替代对照已出（egui / iced / Slint，见回复与 UI 调研 2.3），复拍前本项按"已定但可复议"处理。复拍要点：UI 质感取决于设计而非渲染层；原生方案的代价是组件/富文本生态自研。

### D6 存储层 = SQLite + sqlite-vec + FTS5 【已定】
- 结论：记忆存储用 SQLite 单文件库组合，L1 / L2+L3 / L4 分三个库文件；LanceDB 为超限备选。
- 依据：零服务、三平台、VACUUM INTO 备份、事务+追加式表设计贴合腐蚀公理（记忆调研 1.1）。
- **附加条件（迁移阈值，满足任一即触发"换内核评估"，不自动换）**：
  1. 单库向量行数 > 200 万；或
  2. 检索 P95 延迟 > 200ms（本地 CPU、当前硬件）；或
  3. sqlite-vec 发布破坏性变更且无平滑迁移路径。
  （阈值为工程初值 [待磨合]，随实测校准；写死阈值是防"规模超限再换"沦为空话。）

### D7 嵌入模型 = 双候选实测定档（bge-m3 vs Qwen3-Embedding-0.6B）【修正待拍】
- 原拍板：bge-m3 主力（实测后转正）。**实查修正**：Qwen3-Embedding-0.6B（一手 README 实锤）为 0.6B / 32K 序列 / 1024 维 / MRL 可变维度 / 指令感知 / 100+ 语言，且有同族 Qwen3-Reranker-0.6B 配套；ModelScope 国内直连下载（部署便利显著）。bge-m3 为 8K 输入。
- 修正结论（待作者确认）：实测对比对象改为二者，中文小样本实测后定档；**推荐 Qwen3-Embedding-0.6B 倾斜**（32K 输入 + 同族 reranker + 国内下载），bge-m3 转对照。实测先行、转正后才写主力。

### D8 推理运行时 = ONNX Runtime 【已定】
- 结论：嵌入与重排模型的执行引擎用 ONNX Runtime（跨平台 CPU 构建明确、MIT、C API 语言面最广）。
- 依据：UI/记忆调研 1.3。
- 附加条件：与 D5② 同走逐库过审门禁（铁律 3 落地）；ONNX 转换/量化工程自担（记忆调研风险节）。

### D10 检索策略 = 双路召回 + RRF + 查询时时间衰减 【已定】
- 结论：BM25（FTS5）+ 向量（vec0）双路召回，RRF 融合，时间衰减与置信度纯查询时计算（不写回、只追加），reranker 按 CPU 实测决定开关。
- 依据：与腐蚀公理一致（历史原样保留、衰减可追溯）；RRF 参数少无训练（记忆调研 1.4）。

### D11 L4 共享记忆层 = 独立库文件 + 窄接口 + 先单机 【已定】
- 结论：shared.db 独立库文件，读写走窄接口，先单机；跨机共享不预建（届时再议服务化路线）。
- 依据：与概念总纲组件 4（记忆 L4 为并列独立组件、只传结构化痕迹）逐条对得上。
- **跨 agent 预留（后话，但 schema 首日留字段）**：痕迹表首日带 scope（作用域/来源 agent 标识）、source、confidence 字段——参照成熟记忆引擎的接入友好性来源（窄接口 + 命名空间隔离 + 标准操作集）。只留字段不开接口，实现仍单机。

## 二、待拍（2 项，降级版——交叉验证方建议降级，主代理校验后认同）

### D4 共享核心模式 = A 先行 + 事件契约首日定死 + B 按需 【待拍】
- 降级内容：原推荐"C 混合双轨（A 同进程 + B 独立进程并存）"降级为"A 同进程先行，B（独立进程 + RPC）只保留协议草案不实现"。
- 校验结论（主代理独立判断）：**认同降级**。B 形态的消费方（无头/远程/多客户端）当前一个都不存在，双轨=接口双轨+测试矩阵翻倍，与"抽象全是后补的"（业界调研共性第 3 条）和概念层"禁预建框架"直接冲突。
- **校验补丁（对降级版的修正，须一并拍）**："协议草案"升级为"事件契约首日定死"——事件结构（含审计/留痕所需字段）第一天以结构化 schema 定义，进程内直推与未来 IPC 消费同一契约。这不是预建框架，是概念层"网关单一事实源 + 事件留痕可回放"（公理三/四）的最低要求；将来补 B 时测试矩阵不翻倍（同一套事件 fixture 过两种传输的契约测试）。
- 终态仍是 C，只是不提前付双轨代价。

### D9 记忆集成模式 = 窄接口边界先立 + 进程分离按需 【待拍】
- 降级内容：原推荐"语言无关的独立记忆服务进程"降级为"记忆读写窄接口（模块 API 面）首日定死，进程分离按需再上"。
- 校验结论（主代理独立判断）：**认同降级**。当前唯一记忆消费者是核心自己，写入裁决收口单入口用"一个模块 + 窄接口"即满足，独立进程的 IPC/生命周期管理是纯开销；且原推荐在核心语言未定（D1 现已定 Rust）前锁集成形态确实越位。
- D1 已定 Rust 后复评结论：进程分离的收益只剩崩溃隔离，优先级降为"出现第二消费者（远程/多客户端）时再议"，与 D4 的 B 形态同步决策。
