## 四、新执行序（T 序列）

### T1 TUI 打磨（当前主战场）
1. **流式丝滑**：实测卡顿根因（SSE 分块节奏 vs 渲染合并策略）→ 修根因，逐字输出；
2. **鼠标全操控**：点击选择 / 菜单 / 审批弹窗 / 拖选复制（crossterm 鼠标事件已捕获，补处理）；
3. **hub 主页（两态布局）[已定]**：初始态 = 大 Logo + 空白对话框（形态参照主流 TUI 主页）；运行时 = Logo + 对话框上移顶栏（Logo 左上、对话框在 Logo 右侧），下方左 1/3 历史对话列表（鼠标可滚动）、右 2/3 Token 消耗总览（热力图 / 累计 token / 平均缓存命中等，统计走事件聚合）；hub 顶栏输入 = 新开对话，会话执行与追问归 worker 新终端。干预透明显示见 §三.12（对话内灰色弱化，非独立面板）；
4. **双终端**：hub/worker 进程模型（主页常驻 + 会话弹默认新终端跑执行）；两端统一从事实源（轨迹/会话库）取数，禁止各自维护状态；**并发不设人为上限 [已定]**——指并行会话 run 数不设人为上限，统计按 run 记账天然隔离，不引入并发限制机制；子代理并发是否另设限【待磨合】；参考实现的 `--max-agents`（1–6，默认 6）系其自身实现取舍，不作为我方约束（机制依据见 docs/survey-competitor-mechanisms.md）；
5. **统计聚合层**：usage（已进事件）→ 按任务/日聚合 → 终端热力图渲染。

完成定义：用户旅程走通（敲 sdagent → 主页 → 输入回车 → 弹终端跑会话 → 主页可查历史/统计）+ 回归不回退。

### T1.5 代码卫生（与 T1 并行，纯重构不改行为，回归护航）

## 六、风险与边界
- 双终端跨进程：Windows 默认终端调用（wt / conhost fallback，Linux 终端按平台查表）假设可用，实测为准 [待核验]；
- hub/worker 状态一致性：统一事实源取数（concept-v2 §8 观察面）；worker 被杀留半截轨迹按桌面同口径处理（读侧容忍半行，T1 起补终态事件）；
- 文件地盘互斥：T3 只碰 src/context.rs（及新增 prompt 位），T1/T4 只碰 apps/，T2 只碰分发脚本/入口；
- demo/开发改动全部受 git 管控可回滚；bash 白名单雏形不裸执行（初版边界仍有效）；
- 公开仓库脱敏纪律不变；凭据零入库零打印（环境变量/本地配置，gitignore）。

## 七、版本号规划（2026-10-05 拍板）[已定]

- 版本语义：语义化版本号；**0.x = 快速迭代期**，1.0 = 私人助理可用。
- `0.1.0-alpha.N` = TUI 重写 demo 期（每轮 demo 迭代递增 N）；
- `0.1.0` = TUI 最小闭环定稿（用户旅程全通）；
- `0.2.0` = 分发链（统一命令 `sdagent` / 安装注册）+ 统计聚合；
- `0.3.0` = 系统提示词落地 + 核心机制首件；
- `1.0.0` = 长期目标（概念书五层地基可自查）。
- 版本号唯一出处 = 根 Cargo.toml（workspace 统一）；壳层 `--version` 与状态栏显示同源（同读该出处），任何界面/命令不得手写版本号。
- 状态：版本号规划口径 [已定]；根 Cargo.toml（workspace.package）接线与 `--version`/状态栏同源显示已随 TUI 重写落地（0.1.0-alpha.1，实测 doctor/`--version`/状态栏三处一致）。
