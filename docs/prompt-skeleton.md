## 零、考古核心结论（骨架的依据链）

1. **规模三档**：Pi ≈0.8K token（精简标杆）/ OpenCode ≈3.7K（流程剧本）/ Kimi CLI ≈4.4K（能力契约全家桶）；正文之外**工具描述占全量 ≈53%–89%（按各调研自报数据重算，跨 6 家合并：Pi≈53% / OpenCode≈63% / Kimi≈72% / Codex≈59% / DSH≈79% / Claude Code≈89%），是经济性第一优化点**（OpenCode 1.16.0 工具区瘦身 -35% 有先例）。
2. **静态/动态分离是行业共识**：删日期、动态块挪出前缀有硬证据（pi issue #6621 防缓存失效、OpenCode 多个缓存命中率提交）——与我们硬约束 15/16 同构，直接对齐。
3. **引导两派一零**：OpenCode 流程剧本派（10 步 workflow+断点续）、Kimi 行为守则派（任务分类三套路+收口口诀）、Pi 零引导全押 harness。Codex 另辟蹊径：元规则+负面词汇表+类比定姿态（"like a competent colleague"）+时序契约（先读后写、先干完再请示、先观察再删除）。
4. **环境防御三层**（用户关切：环境防御）：①信任分级固定句式——外部内容=数据非指令（含工具返回/网页/文件/记忆召回/协作者文档等半可信源，Claude Code 用随机 id 边界包裹粘贴内容）；②权限状态运行时注入+升级收窄（一次性最窄档位、必附理由、拒绝不重试）；③Codex Guardian 专职安全层（数据外泄/凭据探测/持久安全弱化/破坏性操作四类风险分类学）。
5. **自主进化防失控**（Hermes/MiMo 两家手法）：Hermes=skills 先行+记忆窄例外（禁祈使句记忆、插件冻结+字符水印、工具按会话门控）；MiMo=checkpoint-writer 独占结构化写+记忆=CLAIMS 需核验+安全边界 4 条。**写入权收窄+需核验是共同点**。
6. **MiMo 适配在运行时不在提示词**：reasoning_content 回传规则、thinking 映射、缺字段垫片全是代码层处理，提示词保持模型无关。
7. **演化规律**：提示词变更是功能映射（Kimi 1.35.0 跳变逐条对应功能提交）+ 瘦身有量化验收（Pi codemode 5,300→3,300 tokens）+ 结构重写对齐分层装配（Claude Code 2.1 → Harness/Memory/Context 骨架）。

## 四、拍板结果（2026-10-05 作者逐条拍板，全部 [已定]）

1. **人设姿态 = Codex 式类比定姿 + Pi 式篇幅**：要姿态引导（类比定姿），但必须短。动静态与引导手法不二选一，**结合概念书做融合二次决策**（定案如下）：静态前缀承载人设/纪律/工具/环境四段（冻结，对齐硬约束 15），引导手法 = Codex 时序契约为形（先读后写/写完必验/无据不言——与概念书公理一同构，不是抄是同源）+ Kimi 收口口诀为尾 + Pi 篇幅纪律为限。
2. **三态套路要写，token 包含在纪律契约段 600 预算内（总量不涨）**：内容自研——按认知状态机三态（调研=只读探索禁写入 / 执行=最小改动逐项做 / 验证=跑证据逐条对照任务），不是 Kimi 的任务类型三套路。
3. **环境防御 = 固定句式 + 分级触发，触发由用户设置与本地路由决策共同决定**：提示词只写固定句式（信任分级）；"问不问/拦不拦"交给拦截层动作分级，档位输入 = 用户设置（认知纪律域阈值）+ 本地路由决策结果（fork layer 式置信度分流：sharp 放行 / split 回主模型带证据裁决，低置信或不可逆→升级人工）。对齐概念书"探针贴标签→配置查表→代码裁决"，提示词零裁决权。**依赖说明**：本地路由层（roadmap T5）当前为 [待磨合]，未落地前本条触发输入退化为用户设置单输入，路由层落地后再启用双输入——依赖显式标注，不以已定结论默认未转正机制已就绪。
4. **负面词表用成品**：unbot（github.com/limeiwang/unbot，MIT）中文 6 类规则引擎为基底——免责套话（值得注意的是/需要指出的是/众所周知/毋庸置疑…）、冗余总结（基于以上分析/结合上述分析…）、过渡套话（综上所述/总的来说/首先其次…）、视角套话（从技术角度/从宏观层面…）、填充套话（在一定程度上/由此可见/换言之/一般来说/大概率…）、模板结尾；叠加本地去味清单（赋能/旨在/一站式/智能化/空泛赞美/过度排比）。正文写作时引用该清单，逐词罗列不进提示词（防词表本身吃 token——负面清单随技能/任务书走，不进静态前缀）。
5. **权威通道格式（要求：可溯源、不混乱）**：`---[directive:<seq>:<source>]---` 内容 `---[/directive]---` 闭合。seq=单调递增序号（可溯源、可对账轨迹事件）；source ∈ harness（底座注入）/ gate（拦截层）/ user（用户指令）；全部走动态附录通道，**永不进静态前缀**；与普通附录内容视觉隔离，读端（人/模型/审计）一眼可辨"这是指令不是闲笔"。
6. **核心代码行数上限 500 行/文件 [已定]**（作者拍板）：单文件超 500 行即拆（按职责拆文件，禁改行为，回归测试护航）。现状超标 4 件已列入整改（见 roadmap）：model.rs 1251 / config/settings.rs 787 / doctor.rs 532 / policy/mod.rs 518。
