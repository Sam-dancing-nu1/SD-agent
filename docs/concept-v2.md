## 一、定位

面向重度工程开发者的自研 Agent 运行时底座（Harness）。纯自研、零重型第三方框架、零现金成本约束。
**核心命题（作者原话）**："拔高能力上限是假的，只是尽可能地守住模型的底线，不要让它浪费时间、人力、物力、金钱、token。"[已定]
落成设计语言：它不追求拔高模型能力上限，只尽可能守住底线——用工程纪律和验证闭环，兜住模型的幻觉、遗忘、散漫与失控；最终目的是不浪费时间、人力、物力、金钱与 token。[已定]

- 目标用户：先适配极重度的 AI 辅助编程开发者（代码与工程是刚需），再向更广用户外扩。形态是私人助理，不是单一编码工具。[已定]
- 核心命题"能力上限 ≠ 运行行为"：同一套模型权重在真实工程会话里会呈现趋同的运行时退化（被质疑就投降、过度服从字面指令、局部信息压过全局目标、长上下文被早期结论支配、反复调用同类工具却无真实推进）。这不是 bug，是对齐后的稳定行为，必须由底座在运行时兜住。[已定]
- **智力放大器边界**：底座接管的是"规则的制定权与裁决权"（路由、风控、放行、干预时机、阈值），**绝不接管模型自身的推理、规划与工具使用**。把模型压成"只输出字符串的通道"，会把底座退化成死板网关，等于主动放弃上限。纪律外置 ≠ 剥夺自主。[已定]
- 形态描述：它不是"更聪明的聊天机器人"，而是**带强制作业规程与自动化质检的软件工程工作台**；模型是工作台上的高级外协，底座是拿着规程盯工序、逼"先读后写、写完必验、无据不言"的项目经理。[已定]

## 二、四条公理

**公理一：下限公理**
模型是高智力、低纪律的执行体。Agent 的全部价值在于注入"工程师/博士生思维"：无证据不发言、先读后写、写完必验证、禁口头完工、失败必复盘。任何依赖模型自觉的设计都是 bug。
**边界说明**：注入的是纪律，不是枷锁。模型多数时候并不比人笨，过度限制反而会让它降智；但不限制又更容易出问题。设计必须找"限制"与"自主"的**平衡点**：纪律只兜运行时退化，不压制智力发挥。

**公理二：纪律外置公理**
边界、条例、权限、流程、路由、风控的**制定权与裁决权**，一律以结构化配置与代码逻辑表达，不交给模型，不与模型进行自然语言博弈。模型只负责填空与生成，不负责制定规则，也不负责裁决自己的行为。
**边界说明一**：本公理约束的是"规则从哪来、由谁裁决"，**不约束 Harness 如何对模型施加干预**。Harness 对模型的单向提示词注入（纠偏、熔断提示、干预告知、环境引导）是执行手段，属于允许且必需的能力，不构成博弈。
**边界说明二**：本公理**不授权**底座去替模型思考。接管的是裁决权，不是推理权；底座可以限制模型"能做什么、以什么纪律做"，不可以替模型决定"问题怎么解"。

**公理三：腐蚀公理**
一切自动化更新链路（记忆整合、配置热更新、自愈修复、技能改写）都会腐蚀人工治理成果。推论：人工标记不可被后台任务覆盖；更新只许追加留痕、不许静默重建；变更必须可回滚；自愈必须限次熔断。

**公理四：上下文不可靠公理**
上下文会被压缩、被污染、被截断，随时可能丢失。推论：唯一副本绝不放在上下文里；关键状态外置持久层；产物落盘留痕；一切结论事后可复查（重查真实存储，禁内存对账）。

## 三、架构地基（五层工程）

底座的工程纵深由五层工程地基构成，缺任一层即出现能力空洞。五层工程地基不是并列，而是由下往上的支撑关系。[已定]

1. **提示词工程**：动态组装、按系统/工具/环境适配、最小必要注入。目标不是超长系统提示词，而是低注入量、低 token 成本；提供多种提示词输入方式，避免模型因描述不足而调用不起工具、或为寻找工具浪费上下文。
2. **上下文工程**：上下文预算、缓存命中、摘要与压缩、关键证据固定、记忆召回注入、工具结果裁剪；防止上下文污染与"早期结论支配后续推理"。缓存命中率是成本的决定性杠杆，运行时动态元数据必须与静态前缀物理隔离。
3. **Harness 工程**：运行时、插件、工具、权限、门禁、审计、隔离环境、热更新、自我修改限制、用户反馈、状态管理。
4. **循环工程**：任务循环、工具调用循环、反思循环、验证循环、失败重试、死循环检测、进展度量、最小化干预。
5. **图工程（编排）**：单执行体与多执行体、角色分工（星座）、任务分发、路由、交接、汇总、冲突仲裁、结果验证。

## 四、架构组件（十二件）

### 1. 本地感知探针（决策前置）
定位：探针是底座里**常驻、近零成本、贯穿全生命周期的唯一"始终在线"的智能组件**（L1 零成本、L2 近零成本）；大模型是"被按需叫来干活的临时工"。它只输出**标签与校准置信度**（低置信升级人工，阈值按后果分级），不输出**裁决**；裁决由配置查表完成。[已定]

**三个作用点**（共用同一个本地模型实例或同类模型的不同微调版本，常驻内存）[已定]；实例的具体形态待磨合 [待磨合]：
1. **思考强度主动切换**：任务进入底座时对原始输入做一次本地分类，输出"档位 + 领域"标签与置信度，由配置查表决定路由到哪一档模型端点。模型自己不需要知道自己在哪个档位。
2. **进度阻塞检测与最小化干预**：持续监听工具调用流与状态流转，维护滑动窗口（工具名 + 参数哈希、输出向量、当前状态与流转历史），带置信度判定"确定死循环 / 伪进展 / 状态振荡"，按分级触发干预，低置信升级人工。
3. **安全与风险拦截的精度提升**：对"工具名 + 参数 + 当前任务上下文"做本地语义级风险评估，输出风险标签与校准置信度，交配置查表决定放行 / 标记 / 阻断。目的是同时压住"漏拦截"（换一种写法就绕过）和"误拦截"（正常操作被反复弹窗）。

**分层递进**（先立住零成本层，再上模型层）[已定]：
- L1 确定性规则与哈希（零成本，先行立住）[已定]
- L2 本地轻量分类模型（本机运行，比规则懂语义、比大模型便宜数个量级；定位主力层，收益须实测后转正）[待磨合]
- L3 **决策链上不设大模型层**：路由、风控、放行、干预与否的判定不得引入大模型推理（否则等于把裁决权交回模型自觉）。异常情况只能"上报"给人或进入人工确认，不得由大模型自行裁决。[已定]
- 探针的判定阈值**参数化**，随当前认知纪律域加载，分类器本身不变。[待磨合]

**动作分级与放行**（用于避开"人工 YES / YOLO"两难）[待磨合]：
- 只读操作、本地可逆修改：自动放行 + 记录
- 代码写入：差异审查 / 可回滚
- 文件删除、网络写入：谨慎，附风险解释
- 发布 / 部署 / 支付类：默认人工确认
- 不可逆系统操作、高危 shell：默认走隔离环境，必要时人工确认

关键：**误报的高风险必须能被降级为自动放行**，只有真高风险才弹回用户；人工确认入口必须附带风险解释。判定依据是工具类型、参数、可逆性、影响范围、历史行为、用户偏好与隔离环境结果，**不是模型自称安全**。

### 2. 配置档案与认知纪律域（专武 Profile）
三类档案 [已定]：
- 环境档案：系统 / shell / 编码 / 路径约定 / 网络差异，显式写入，禁止依赖模型自行适配。
- 模型档案：上下文窗口 / 缓存机制 / 调用格式 / 风险阈值 / 预算。
- 任务档案：高频任务的固定流程与验证器绑定。

**认知纪律域（简称"域"）**：以"认知姿态"为主键的配置包，进入某个域时**真实切换三样东西**——提示模板、工具白名单、决策阈值。关键是"真实切换"：不是提示词里写"你现在是架构师"，而是代码层三个变量真的换了值；同一个操作在不同域里可以判出不同的风险等级。[待磨合]
- **域 ≠ 多执行体**（正交的两根轴）：**域 = 同一个执行体换一副纪律**（进程、上下文、缓存流不变），解决单执行体内的注意力/权限/阈值漂移；**多执行体 = 另开一个上下文**，解决并行与污染隔离。用域能解决的事不要开执行体，反之亦然。
- **切换是显式动作**：可由用户在界面切换，也可由探针**建议**切域、经用户确认或否决；切换本身是一个生命周期事件，必须在观察面可见（当前域、工具白名单规模、风险阈值）。[待磨合]
- **粒度判据**：只有当"这个场景的工具白名单或决策阈值与前一个真实不同"时才立新域；只是口气不同那是角色扮演，合并。[待磨合]
- **数量收敛**：域数量由缓存工程的成熟度决定——切域便宜了，域才可以多；在"切域不毁前缀"跑通之前，域数量必须收敛（先立少量核心域，与其对应状态机的核心状态）。[待磨合]

由结构化表单生成与修改；切换档案即切换底层行为，不改代码。变更纪律：落盘 + 回读验证 + 显式生效时机，不假设热生效。

### 3. 认知状态机（SOP 引擎 / 认知虚拟机）
强制有限状态流转：调研 → 计划 → 执行 → 验证 → 沉淀。[已定]
- 每状态有准入工具白名单与流转前置条件（未调研禁止写入、未验证禁止宣告完成）。
- **流转守卫**：定义流转矩阵与前置条件；模型试图跨状态跳跃（未调研直接写入）时，引擎拒绝流转并向模型上下文注入最小纠错提示（"当前处于调研阶段，禁止写入，请先读取目标文件"）。[已定]
- **证据强制绑定**：模型写出的任何结论/完成声明都是一个"主张"，主张必须绑定由代码执行得到的确定性证据（测试、编译、静态检查、真库重查）。证据缺失或不通过 → 主张降级为"未经证实"，在观察面标红并阻止进入沉淀阶段。[已定]
- **有界验收**：不是每一轮都追加一次验收，只在触发条件满足时才进入强制验收（省 token、少污染主线）。触发条件表待磨合。[待磨合]
- **收敛检测**：以每轮的"状态指纹"（工具调用集合、被改文件集合、验证结果等）判定三态——**收敛**（指纹连续多轮不变，可能已无新进展但目标未达成）、**发散**（指纹持续变化且目标状态推进，正常）、**振荡**（指纹在少数几个值之间循环，典型死循环）。三者皆纯代码可判定。[待磨合]
- **干预分级**，由配置与域阈值决定：L1 最小干预（向下一轮注入一条结构化纠偏提示，不动记忆）；L2 策略切换（清空工作记忆、回退到计划状态、强制重新规划）；L3 挂起（暂停任务、通知用户、等待人工指令）。[待磨合]
- **死循环与伪进展**触发熔断：挂起任务、清短期记忆、注入反思提示、向用户透明反馈"harness 已介入"。[已定]
- 干预哲学：最小化干预 + 全程透明。不破坏模型的深度思考，但卡壳与偏航必须被兜住。干预由代码裁决，不由模型自行决定；每次干预都必须广播、可审计，用户必须知道"干预了、干预了什么、为什么"。[已定]

### 4. 记忆系统（纪律型记忆）
记忆五层（含共享层）。**记忆系统计为十二件中的一件，内部含私有记忆与共享记忆两个独立子组件。**[已定]
**私有记忆（L0–L3）与共享记忆（L4）是两个独立组件，一样重要、相互耦合**：共享层的成熟内容可被私有层检索吸收，私有层验证过的经验可上浮共享层；两者只通过结构化痕迹耦合，不互传原始对话。[已定]
- L0 工作记忆：当前目标与证据，含目标锚定区（初始目标与核心约束钉死，防漂移）。
- L1 情景记忆：全量执行轨迹，只按时间窗口 / 事件类型检索，不全量召回。
- L2 语义记忆：结构化事实 + 向量检索，每条带证据来源、置信度、时间戳、作用域。
- L3 反思记忆：异步提炼的高阶经验 / 心智模型 / 踩坑记录。
- **L4 共享记忆层（间接协作层）**：与私有记忆并列的独立组件，面向多执行体协作的全局共享记忆。执行体之间不传原始对话，只写入/读取结构化痕迹（来源、时间戳、置信度、作用域、目标锚定、证据），痕迹自带衰减。完成判定 = 痕迹能被下游执行体或验证器读到并采纳，而不是上游自称完成。[待磨合]

纪律：
- 写入必有证据来源与置信度，无证据降级为"信念"；入库前矛盾检测（相似但语义相反的新事实触发人工确认或降置信度）。[已定]
- **职责分工**：模型负责"理解与提取"，代码负责"存储、合并、衰减、检索决策"。模型不直接读写记忆存储，只能提出操作请求，由代码裁决。[待磨合]
- 人工标记不可被自动任务覆盖（腐蚀公理）。
- 生命周期由代码执行四杠杆：重要性、合并、时间衰减、驱逐。
- 检索 = 多路混合检索（语义 + 关键词 + 实体关系 + 时间）+ 轻量重排 + 硬性 token 预算截断，宁缺毋滥。
- **轻重分治与注入时机**：轻索引（目标锚、"去哪查"的指针、画像）每轮随上下文注入且必须轻；深记忆不默认注入、按需检索，且在执行体开始工作**之前**一次性注入，不在其运行过程中反复查库（运行中检索实践经验更差）。[待磨合]
- 需要时主动向模型反馈（关键词命中 / 向量检索 / 联想），及时纠正偏移。
- 反思异步批量限量执行，不占实时推理；反思层不可由"只存储"替代——跨案例比较（哪些步骤在成功轨迹里反复出现）必须由独立反思层完成，"存了 ≠ 会了"。
- **整合升维**：零散事实经整合（去重、去矛盾）升维为观察，观察再沉淀为可复用知识（技能 / 知识页）；沉淀层只从观察构建，不从原始事实直接构建。[待磨合]
- **经验不止一种容器**：至少分三格——事实与坑（记忆）、可复用流程（技能）、代码结构（依赖索引），否则反思出的东西每次都要模型重新理解一遍。[待磨合]
- **时序有效性**：事实带生效窗口，可让过期事实失效、同时保留其历史上下文（知道"曾经成立过"）；矛盾检测必须与置信度衰减、TTL 配套使用，否则过期事实会长期压过新事实。[待磨合]
- **召回优先级**：用户策展的心智模型 > 自动合成的观察 > 原始事实；反思是**迭代推理**（反复查记忆、比对心智模型与观察后再作答），不是一次检索。[待磨合]
- **实体归一**：同一对象的不同指称在入库时归并为同一实体，避免同一件事分裂成多条互相矛盾的记忆。[待磨合]
- **作用域隔离**：会话级 / 用户级 / 仓库级 / 域级，互不污染；"必须跨域存活"的约束沉到对应作用域，而不是靠对话历史承载。[待磨合]
- 存储走数据库（关系型 + 嵌入式向量），拒绝纯文档存储（费 token 且依赖模型自觉解析）；不引入独立重型图数据库，实体关系用关系表/邻接表表达。
- **记忆与缓存的关系**：记忆系统控制的是"增量附录的体量"（用结构化事实替代整段历史），**不负责前缀稳定性**；前缀稳定只能靠底座的冻结机制。记忆是"税"不是"红利"——它自带三项生产开销：写入纪律成本、与提示缓存的冲突、跨模型适配。[待磨合]
- **对外提供记忆适配接口**：自研记忆是深度结合的主通道；允许接入外部记忆系统，但能力可能降级，由用户自行承担。

### 5. 上下文与成本工程（前缀冻结）
提示缓存按前缀匹配：前缀里改一个字节，从该点往后全部失效。因此"切换工具集/切换认知纪律"这类动作天然是成本动作，必须用工程手段处理。[已定]

- **四段结构**：冻结基础前缀（内核提示 + 全量工具目录骨架，会话内不重写）→ 当前域快照（该域的纪律提示 + 白名单映射 + 阈值表）→ 对话历史（只追加、不重写）→ 增量附录（探针标签、任务状态、记忆召回、痕迹注入；每轮可变，绝不进前缀）。[待磨合]
- **切域协议**：不重写旧域快照，而是在其后**追加一个新域快照**，并把旧快照标记为已退役。旧前缀原封不动，缓存继续命中，只有追加点之后需要重新计算。[待磨合]
- **纪律与能力分离**：工具白名单的收紧靠**拦截层**执行，不靠从提示前缀里删除工具定义——能力上限（全量工具目录）留在缓存里，运行纪律（当前可调用子集）移到拦截层。这正是"上限相同、下限不同"的落地方式。[待磨合]
- **边界压缩**：当退役快照堆积导致上下文虚胖时，只在"域边界"这一特定位置把已退役快照压成摘要，保留当前域快照与缓存锚不动；压缩是显式事件，全程记录可审计（压了什么、丢了多少），不做静默丢弃；压缩也可以被做成在"有意义的停止点"上显式触发的可调用动作，并附带明确的触发条件。[待磨合]
- **压缩禁区**：压缩不得改写标识符（唯一标识、哈希、路径、端点等），一旦被摘要改写会造成静默错误。[待磨合]
- **长尾约束不得躺在历史里**：像"改 X 必须同步 Y"这类长尾纪律，最容易被压缩器当成"已解决的上下文"丢掉；它必须沉入按作用域隔离的持久层，并在切域/压缩之后由底座**强制重新注入**固定区。[待磨合]
- **增量累积而非每轮重写**：每轮重写整个上下文会被压成有损摘要并严重损害准确性（"简洁偏见"：来之不易的领域细节被压成通用短句；"上下文崩溃"：逐轮重写导致信息崩塌）。正确做法是把上下文当作条目化、持续累积并精炼的手册，只做小增量更新，更新代价极低。[待磨合]
- 上下文工程动作可归为四类：写出（把中间结论落到窗口之外）、选入（按需拉入）、压缩（精简）、隔离(交给独立上下文的执行体)。[已定]
- 目标锚定区：无论上下文如何压缩或演化，初始目标与核心约束必须钉在固定区域。
- 运行时动态元数据必须与静态前缀物理隔离；高频变动变量绝不进系统提示词。

### 6. 事件、网关与审计（分级事实源）
所有状态变更、工具调用、拦截动作过统一事件总线，持久化为唯一事实源（断点恢复 / 审计 / 监控共用）。[已定]
- **网关是单一事实源与唯一入口**：工作面、观察面、远程端、审计层、决策组件、记忆系统都从网关取数，不各自维护状态。
- 事件须规范化封装（类型、负载、追踪标识、时间戳），支持多订阅者扇出，支持同步（阻塞等待决策）与异步（观察不阻塞）两种订阅模式。
- 多个守护订阅者的决策合并遵循"一票否决优先"：任一否决即阻断。
- 订阅者各自熔断（单个订阅者故障不得拖垮总线）；会话之间相互隔离；总线与具体传输方式无关。[待磨合]
- 分级处置：只读异步放行 + 记录；写入同步记录 + 限流；高危同步阻塞 + 人工批准 + 风险解释。
- 破坏性操作走"隔离执行体 + 干净上下文 + 事后独立对账"模式。
- 断点恢复用事件追加 + 定期快照，不做全量写库。
- **安全前提**：生命周期钩子与插件元数据是可被篡改的攻击面（供应链劫持），必须由网关统一治理与审计；出站内容须经脱敏订阅者过滤；高权限能力面（桌面感知与输入控制、浏览器驱动、系统自动化）默认落在高阈值域，并由风险标签 + 白名单双重管住。

### 7. 生命周期钩子与单一调度入口
- **五个生命周期阶段**：会话开始（加载档案、初始化目标锚、注入记忆快照、一次性写入静态前缀）→ 输入到达（探针第一次贴标签、构建检索查询、预算预检）→ 工具执行前（探针第二次贴标签、查表决策放行/阻断/询问、审计记录）→ 工具返回后（抽取运行时证据、写入痕迹层、更新工作记忆、触发收敛检测）→ 停止与压缩前（反思与沉淀、执行记忆四杠杆、生成可审计报告）。[待磨合]
- **压缩前是一等事件**：上下文压缩必须可拦截、可观测、可干预（决定是否压缩、压到什么程度、压缩后如何重排以保住前缀），不是内部黑箱。[待磨合]
- **单一调度入口**：所有钩子必须走同一个调度入口，禁止散落在各调用点。否则会出现多个互相看不见的观察者对同一动作给出互相冲突的判断。[待磨合]
- **同步/异步严格分离**：只有决策链（感知 → 查表 → 阻断）是同步的，且只有它能阻断；观察者（审计、监控、记忆写入、痕迹写入）一律异步扇出。这同时解决"事件风暴阻塞吞吐"和"高危动作抢在判定前执行"两个问题。[待磨合]

### 8. 观察面（双终端）
工作面与观察面物理分离，统一从事实源取数。[已定]
- **两个终端**：一个专门干活；一个专门显示实时用量、token 与缓存命中、任务状态机进度、当前认知纪律域、探针标签与拦截动作、干预记录、记忆读写审计、事件流。
- 必须可见"给模型注入了什么、干了什么"：注入内容与动作可追溯。
- 前端形态可插拔：终端形态优先，图形 / 移动端为可选消费者；支持多设备只读接入与远程审批。
- 远程只做查看、审批、指令下发；执行以本机事实源为准，远程不得绕过。
- 界面承担**结构化引导**职责：边界、条例、引导不靠自然语言与模型博弈，而是通过表单/滑块在界面侧配置好，落成配置文件由代码执行；重度任务可显示固定流程的导航进度（当前步骤、等待确认、可跳过/回退）。

### 9. 能力供给与扩展（插件面）
模型能力空间由五类入口供给，全部以可插拔方式挂载 [已定]：
- 技能包（可复用的任务能力单元）
- 工具与上下文接入协议（外部能力接入）
- 外部事件回调（被外部系统触发）
- 定时调度（按时间触发）
- 隔离执行环境（受限沙箱内运行）

纪律：
- **整个 Harness 必须低耦合**，能力以插件方式拼装；这是高自由度的前提。
- 一份能力应能被多种宿主复用（宿主无关的能力形态），但能力的进出只能经过网关、标签、白名单、检查点四处，不允许自由进出。[待磨合]
- 权限分级：读 / 写 / 执行 / 网络 / 安装 / 自我修改 / 调度 / 远程控制，逐项授权。
- 自我进化与自我修改 = 提议 → 评估 → 人工确认 → 落盘 → 显式生效；代码级范围界定（白名单外一律拒绝）+ 离线评估门 + 人在回路；限次 + 熔断 + 留痕 + 可中断。
- 门禁一旦发现异常，直接注入提示词要求模型纠正，并告知用户。

### 10. 编排（通用型与垂直型）
- 通用型架构：日常助理、通用问答、文件与检索、轻量代码任务，意图不明时的总入口。
- 垂直型架构（多执行体 / 星座，用户的叫法）：按角色分工，用于边界清晰且需要上下文隔离的重任务；每个角色须有明确职责、输入、输出、权限边界与交接协议。
- **主执行体常驻**：它承载缓存前缀、目标锚、痕迹工作区，是"连续性"的载体。[待磨合]
- **辅助执行体按需派生、用完即弃、只回传压缩摘要**，并且"像工具一样"是按需能力，不在主循环主干上；是否派生由代码裁决。[待磨合]
- 多执行体只在任务边界清晰且需要上下文隔离时使用，必须有明确交接协议与最终裁决者；默认单执行体 + 强状态机。[已定]
- **归属判据**（决定一条信息/一个能力该归谁）[待磨合]：
  1. 当前这一轮必须被模型看见的（目标、约束、进行中状态）→ 底座上下文/目标锚，绝不放记忆里等检索；
  2. 过程噪声巨大、只要结论的（大范围探索、批量迁移、跨文件查找）→ 辅助执行体，只回压缩摘要；
  3. 跨会话才用得上且能结构化的（踩过的坑、验证过的流程、偏好）→ 记忆，需要时才读，不默认进系统提示。
- **不共享上下文的执行体不得承担"必须共享决策状态"的活**：多个信息不全的执行体各自决策会产生互相冲突的结论。[待磨合]
- 路由决策权可归用户、可由 Harness 自动判定、可由探针辅助；路由不由模型自由决定。
- 交接传递"痕迹与证据（高阶观察）"而非原始对话，降低噪音与 token。

### 11. 工作区与隔离（版本控制工作区）
版本控制工作区在本底座里不是"版本管理工具"，而是承担四个角色 [待磨合]：
- **状态机与证据载体**：每个域/执行体的产出以工作区差异的形式成为可复查证据（"完成有证据"的物理形态）。
- **物理隔离原语**：主执行体常驻主工作区；辅助执行体各起独立工作区，用完即焚（并行隔离的主流做法）。
- **回滚锚**：切换纪律/自我修改前后打检查点，支持回滚到会话某一点。
- **痕迹格式**：执行体之间不传对话，传"分支标识 + 差异 + 结果文件"。

必须补的缺口 [待磨合]：
- 工作区隔离只覆盖**受版本控制的文件**，不隔离运行时。因此环境档案必须显式管好四件事：端口分配、数据库实例、环境变量注入、依赖锁；否则多开执行体就是给自己埋故障。
- 非差异型副作用（装依赖、改系统配置、写库）最难回滚，必须单独登记，不能只靠回滚差异。
- 隔离必须由底座强制，不能靠提示模型"记得隔离"。

### 12. 自我进化与自我修改
- **进化对象是 Harness 本身，而不是模型权重**：基座模型冻结，进化发生在底座侧（批评家规则、恢复技能、配置、技能库）。这恰好是"提高下限、不提高上限"的工程含义。[已定]
- **运行时批评家必须是代码，不是模型的自我反思**：模型自问自答容易陷入"谄媚式反思"（轻易推翻正确结论、为错误结论找理由）；验证应由确定性传感器（测试、编译、静态检查、真库重查）给出。[已定]
- 能力固化路径：任务级产物 →（经多次回归验证的验证门）→ 可复用技能 →（本设计不做）内化进模型权重。[待磨合]
- 反向进化（为了局部指标损害全局目标）是真实风险；一切变异都要过约束验证器（安全指南、长度限制、输出格式），不合格的变异直接丢弃。[待磨合]
- 全流程：提议 → 评估 → 人工确认 → 落盘 → 显式生效；限次 + 熔断 + 留痕 + 可中断；人工审核不可省略。[已定]

## 五、关键设计思想

1. 标签机 + 查表器 = 风控闭环：探针输出标签与校准置信度，查表引擎下裁决；不可逆操作的闸门由纯代码把守。
2. 模型是外包，Harness 是项目经理：模型出智力，Harness 出 SOP，逼迫模型"先读后写、写完必测、无据不言"；但项目经理不替外包写代码。
3. 记忆是纪律，不是聊天历史：核心价值是防污染、防过载、防幻觉；写入有证据、召回有预算、过期必衰减。
4. 事件流是唯一真相源：监控、审计、断点恢复、防供应链劫持共用同一事实源；钩子走单一调度入口。
5. 成本围绕 token 预算而非金钱：缓存稳定前缀（动态元数据只进消息区不进静态前缀）+ 小模型做提取与反思 + 任务分级路由 + 记账闭环。
6. 注入是手段，不是博弈：规则的制定与裁决靠配置和代码，对模型的纠偏与干预靠提示词注入，两者分工不冲突。
7. 提示词按环境组装：针对不同系统、工具、环境给专门的提示词引导，避免调用不起工具、或为寻找工具浪费 token。
8. 上限留在缓存，纪律移到拦截：能力目录常驻前缀（不破坏缓存），可调用子集由拦截层实时收紧——"任何纪律域都有完成任务的全部能力，只是纪律不同"。
9. 三件正交、互不替代：**域**管"一个执行体内部别跑偏"，**执行体**管"多个上下文别互相污染"，**记忆引擎**管"跨时间不失忆、经验能共享"。用错层级就白干活。
10. 追证据，不追动作：判定"有没有进展"不看模型忙不忙，看有没有产生真实新证据（证据增量），以及状态指纹是否收敛/振荡。
11. 有界干预、有界验收：不是每一轮都插手、也不是每一轮都验收，只在触发条件满足时做最小必要的动作，并全程对用户透明。
12. 参考不是需求：外部项目/方案只是参考材料，取其原理与踩坑，绝不整包照搬，也不因为"能结合"就往架构里塞。

## 六、硬约束清单

1. 记忆写入必带证据来源 + 置信度 + 时间戳；无证据不得入语义层。
2. 自动化任务禁止覆盖人工标记（状态位 / 标签）；更新只许追加，重建式更新禁止。
3. 自愈与自我修改 = 提议 → 评估 → 人工确认 → 落盘 → 显式生效；限次 + 熔断 + 留痕 + 可中断。
4. 配置变更必须回读验证并标注生效时机；禁止假设热生效。
5. 关键产物一律落盘存档；上下文压缩后任务仍可从持久层恢复。
6. 破坏性操作 = 隔离执行体 + 干净上下文 + 事后独立对账（重查真实存储）。
7. 口头完工无效；完成判定只认验证器产出的可复查证据。
8. 启动链单一入口；守护 / 自愈进程只许走同一入口。
9. 环境差异显式写入环境档案，禁止依赖模型自行适配。
10. 决策层零成本优先（规则 / 查表先行），模型调用分级记账，token 预算硬控。
11. 路由、风控、放行、干预与否，一律由探针贴标签、配置查表、代码执行裁决，不由模型作出。
12. 大模型只输出生成物与标签，不输出对自身行为的裁决；但其推理、规划与工具使用自主权不受剥夺。
13. 决策链（贴标签 → 查表 → 放行/阻断/路由）不得引入大模型推理；大模型不得参与对自身行为的裁决。
14. 全部生命周期钩子必须经单一调度入口；同步只允许存在于决策链，观察者一律异步扇出。
15. 上下文基础前缀在会话内冻结、不重写；一切变化以"追加"表达；已退役的配置块只标记退役，不改写历史。
16. 压缩不得改写标识符（唯一标识、哈希、路径、端点等）；压缩必须是显式事件，前后可审计。
17. 必须跨轮、跨域、跨会话存活的约束，不得依赖对话历史承载；必须沉入按作用域隔离的持久层，并在切换/压缩后强制重注入。
18. 辅助执行体只回传压缩摘要，不得回传原始对话；执行体的派生与回收由代码裁决，不作为默认路径。
19. 需要共享决策状态的任务不得下派给不共享上下文的执行体。
20. 工作区只隔离受版本控制的文件；运行期资源（端口、数据库实例、环境变量、依赖锁）必须由环境档案显式分配，非差异型副作用必须单独登记。

## 七、靶子清单（必须兜住的模型短板）

底座的每一条机制都要对应到具体靶子，避免为设计而设计。[已定]
1. 被质疑就投降；无新证据即翻转结论。
2. 过度服从字面指令，忽略隐含约束与全局目标。
3. 局部信息压过全局目标；最近一条消息权重过高。
4. 长上下文被早期结论支配。
5. 反复调用同类工具却没有真实推进（伪进展）。
6. 幻觉：编造文件 / 函数 / 命令 / 结论 / 搜索结果。
7. 上下文过载：关键内容被淹没、开始复读。
8. 目标漂移：用户要 A 做成 B。
9. 工具调用失败：找不到工具、参数错误、反复试错。
10. 记忆污染：错误结论入记忆、过期信息长期影响决策。
11. 提示注入与工具结果污染：外部内容试图改变任务。
12. 成本失控：每轮带全量历史、召回过多、缓存失效。
13. 多执行体失控：角色边界不清、重复劳动、交接丢失。
14. 多设备状态不一致。
15. 自我修改失控：越改权限越大、用户不知情。
16. **执行体之间不共享所学**：各自独立探索、重复踩坑，经验互相不通，越用越蠢。
17. **压缩吃掉长尾约束**：把"必须同步 X"这类纪律当已解决上下文丢弃，之后再也想不起来。
18. **切换纪律/前缀导致缓存整体失效**：一次切域或改工具集，成本骤升。
19. **信息不全的并行决策互相冲突**：多个执行体基于不同信息各自决定，结论互相矛盾。
20. **高危能力面默认开放**：桌面输入控制、浏览器驱动、系统自动化一旦默认可达，等于把供应链攻击入口摆在门口。
21. **把记忆当红利**：误以为记忆系统能顺带兜住缓存与注意力，实际它自带写入纪律、缓存冲突、跨模型适配三项开销。

## 八、待磨合点（下一步锐化对象）

1. 探针三作用点的阈值表（风险分档、阻塞灵敏度、档位映射）与"随域加载"的具体机制。
2. 认知纪律域的清单与数量：先立哪几个核心域，后续按什么顺序扩展。
3. 切域协议的具体编码：追加式域快照的结构化格式、退役标记、与前缀匹配的边界如何保证"只从追加点重算"。
4. 边界压缩的触发窗口与压缩粒度。
5. 收敛 / 发散 / 振荡三态的指纹定义、窗口大小与干预分级阈值。
6. 有界验收的触发条件表（哪些情形才追加验收轮）。
7. 痕迹层的数据结构、冲突合并与衰减参数。
8. 记忆四杠杆的参数模型；作用域（会话/用户/仓库/域）的具体边界。
9. 观察面（双终端）的具体信息架构与表单化引导界面。
10. 事件协议的字段定义与订阅者清单。
11. 插件权限分级的授权界面与回收机制。
12. 运行期资源隔离（端口、数据库实例、依赖锁）的分配与回收策略。
13. 辅助执行体的成本模型：什么时候值得派生、摘要协议如何保证不丢关键信息。
14. 经验三格（事实与坑 / 可复用流程 / 代码结构）之间的沉淀与升级判据。
15. 记忆分层与"检索预算"的比例分配。

**待核验（须实测才能定）**：本机运行轻量分类探针的真实开销与收益（延迟、准确率、误报率）；一切外部参考中的量化结论（命中率、召回率、成本降幅等）只作方向性参考，不得作为本文件的设计依据。

## 九、文档与协作纪律（非系统运行时约束）

以下几条是对**文档写作与协作**的要求，不属于系统硬约束，不得混入第六节：
1. 去工具指向性：架构表述只用通用计算机科学概念与设计模式，禁止绑定具体第三方项目名称与 API——否则本文件喂给任何代码生成 AI，都会诱导它去安装某个具体的包、照抄某个具体实现。
2. 禁虚构：任何"业界做法 / 参考实现"必须有可核验来源才能写入设计依据；核验不到就标注"待核验"或不写。没有记录就说"没有记录"。
3. 禁过度解读：参考材料只是参考，不是必须全部实现的需求清单；不确定用户意图就问，禁止擅自补全，禁止"为了结合而结合"。
4. 结论标注状态：已定 / 待磨合 / 待核验；禁止把"待磨合"写成"已定"。
5. 术语首次出现给一句话定义；用户造的术语按用户的定义用，不擅自改义。
