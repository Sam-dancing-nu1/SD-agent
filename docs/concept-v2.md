## 一、定位

面向重度工程开发者的自研 Agent 运行时底座（Harness）。纯自研、零重型第三方框架、零现金成本约束。
它不提高模型智力的上限，只守住模型能力的下限——用工程纪律和验证闭环，兜住模型的幻觉、遗忘、散漫与失控。

## 二、四条公理（整个体系的物理定律）

**公理一：下限公理**
模型是高智力、低纪律的执行体。Agent 的全部价值在于注入"工程师/博士生思维"：无证据不发言、先读后写、写完必验证、禁口头完工、失败必复盘。任何依赖模型自觉的设计都是 bug。

**公理二：纪律外置公理**
边界、条例、流程、路由、风控，一律以结构化配置与代码逻辑表达，不与模型进行自然语言博弈。模型只负责填空与生成，不负责制定规则，也不负责裁决自己的行为。

**公理三：腐蚀公理**
一切自动化更新链路（记忆整合、配置热更新、自愈修复、技能改写）都会腐蚀人工治理成果。推论：人工标记不可被后台任务覆盖；更新只许追加留痕、不许静默重建；变更必须可回滚；自愈必须限次熔断。

**公理四：上下文不可靠公理**
上下文会被压缩、被污染、被截断，随时可能丢失。推论：唯一副本绝不放在上下文里；关键状态外置持久层；产物落盘留痕；一切结论事后可复查（重查真实存储，禁内存对账）。

## 三、架构骨架（六件套）

### 1. 感知探针（决策前置）
任务输入与动作请求先过本地探针贴标签（风险等级 / 计算力度 / 任务领域），三层递进：
- L1 确定性规则与哈希（零成本，先行立住）
- L2 轻量分类模型（本地运行，按实测收益启用）
- L3 LLM 评估（仅异常时兜底）

大模型对路由与风控没有发言权。探针输出标签 → 查配置档案表 → 下达绝对指令（放行 / 阻断 / 路由 / 注入工具链）。

### 2. 配置档案（专武 Profile）
三类档案：
- 环境档案：系统 / shell / 编码 / 路径约定 / 网络差异，显式写入，禁止依赖模型自行适配。
- 模型档案：上下文窗口 / 缓存机制 / 调用格式 / 风险阈值 / 预算。
- 任务档案：高频任务的固定流程与验证器绑定。

由结构化表单生成与修改；切换档案即切换底层行为，不改代码。变更纪律：落盘 + 回读验证 + 显式生效时机，不假设热生效。

### 3. 认知状态机（SOP 虚拟机）
强制有限状态流转：调研 → 计划 → 执行 → 验证 → 沉淀。
- 每状态有准入工具白名单与流转前置条件（未调研禁止写入、未验证禁止宣告完成）。
- 验证阶段强制触发外部验证器（测试 / 编译 / lint / 真库重查），验证失败强制回退，禁止向用户报"完成"。
- 死循环与伪进展（反复横跳、证据无增量）触发熔断：挂起任务、清短期记忆、注入反思提示、向用户透明反馈"harness 已介入"。
- 干预哲学：最小化干预 + 全程透明。不破坏模型的深度思考，但卡壳与偏航必须被兜住。

### 4. 记忆系统（纪律型记忆）
四层：
- L0 工作记忆：当前目标与证据，含目标锚定区（初始目标与核心约束钉死，防漂移）。
- L1 情景记忆：全量执行轨迹，只按时间窗口/事件类型检索，不全量召回。
- L2 语义记忆：结构化事实 + 向量检索，每条带证据来源、置信度、时间戳、作用域。
- L3 反思记忆：异步提炼的高阶经验/心智模型/踩坑记录。

纪律：
- 写入必有证据来源与置信度，无证据降级为"信念"；入库前矛盾检测。
- 人工标记不可被自动任务覆盖（腐蚀公理）。
- 生命周期由代码执行四杠杆：重要性、合并、时间衰减、驱逐。
- 检索 = 混合检索（关键词 + 向量）+ 重排 + 硬性 token 预算截断，宁缺毋滥。
- 反思异步批量限量执行，不占实时推理。
- 存储走数据库（关系型 + 嵌入式向量），拒绝纯文档存储（费 token 且依赖模型自觉解析）。

### 5. 事件与审计（分级事实源）
所有状态变更、工具调用、拦截动作过统一事件总线，持久化为唯一事实源（断点恢复 / 审计 / 监控共用）。
分级处置：
- 只读操作：异步放行 + 记录
- 写入操作：同步记录 + 限流
- 高危操作：同步阻塞（一票否决），等待人工批准，附风险解释

破坏性操作走"隔离执行体 + 干净上下文 + 事后独立对账"模式。断点恢复用事件追加 + 定期快照，不做全量写库。

### 6. 观察面（可插拔前端）
工作面与观察面物理分离，统一从事实源取数。
- 观察面展示：实时用量 / token 与缓存命中 / 任务状态机进度 / 拦截与干预记录 / 记忆读写审计。
- 前端形态可插拔（命令行优先，图形/移动端为可选消费者），支持多设备只读接入与远程审批。
- 远程只做查看、审批、指令下发；执行以本机事实源为准，远程不得绕过。

## 四、关键设计思想

1. 标签机 + 查表器 = 绝对风控：探针贴标签，配置下死命令，模型对风险没有解释权。
2. 模型是外包，Harness 是项目经理：模型出智力，Harness 出 SOP，逼迫模型"先读后写、写完必测、无据不言"。
3. 记忆是纪律，不是聊天历史：核心价值是防污染、防过载、防幻觉；写入有证据、召回有预算、过期必衰减。
4. 事件流是唯一真相源：监控、审计、断点恢复、防供应链劫持共用同一事实源。
5. 成本围绕 token 预算而非金钱：缓存稳定前缀（动态元数据只进消息区不进静态前缀）+ 小模型做提取反思 + 任务分级路由 + 记账闭环。

## 五、硬约束清单（限定要求，逐条可验收）

1. 记忆写入必带证据来源 + 置信度 + 时间戳；无证据不得入语义层。
2. 自动化任务禁止覆盖人工标记（状态位 / 标签）；更新只许追加，重建式更新禁止。
3. 自愈与自我修改 = 提议 → 评估 → 人工确认 → 落盘 → 显式生效；限次 + 熔断 + 留痕 + 可中断。
4. 配置变更必须回读验证并标注生效时机；禁止假设热生效。
5. 关键产物一律落盘存档；上下文压缩后任务仍可从持久层恢复。
6. 破坏性操作 = 隔离执行体 + 干净上下文 + 事后独立对账（重查真实存储）。
7. 口头完工无效；完成判定只认验证器产出的可复查证据。
8. 启动链单一入口；守护/自愈进程只许走同一入口。
9. 环境差异显式写入环境档案，禁止依赖模型自行适配。
10. 决策层零成本优先（规则/查表先行），模型调用分级记账，token 预算硬控。
11. 架构表述去工具指向性：只用通用设计模式表达，禁止绑定具体第三方项目 API。
12. 禁虚构：任何组件的"业界做法"必须有可核验来源才写入设计依据；核验不到标注"待核验"或不写。
