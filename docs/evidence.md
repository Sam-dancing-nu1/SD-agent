# 实证对账（已脱敏）

> 用途：记录概念体系各概念背后的真实运行证据，是设计依据的证据链。
> 可见性：公开（已脱敏——去标识、去绝对数值、去原话引用、去第三方项目名；本仓库 push 即公开，无内部文档）。
> 方法：早期概念稿（空记忆环境纯推演）的每条概念，用真实运行证据过堂，分三类处置；此后每一轮对账追加新批次。
> 证据分级：**实测事故**（本机真实发生）> **方向性结论**（多方一致、原理明确）> **第三方自述**（厂商或团队口径，未独立复核）。
> 凡第三方自述与单次实测，一律显式标注，不得升格为"已定"设计依据；一切绝对数值只作方向性参考。
> 本轮（续接对话）证据的原始出处在本地素材（对话导出与外部材料，不入库）中可回溯；公开仓库只保留抽象结论与核验分级。

## A. 被实证证实的概念（保留并强化）

| 概念 | 真实运行证据 |
|---|---|
| 记忆必须防污染，不能全存全收 | 真实长期记忆库抽样实测仅约两成内容有效：过程垃圾、过期旧结论、重复各占约 37% / 37% / 11%。垃圾被召回进上下文，是"对话降智"的直接原因（实测） |
| 写入要有证据链/置信度，过期必须衰减 | 已废弃的旧架构设计长期被当作世界事实召回，持续污染决策——过期结论不衰减等于慢性中毒（实测） |
| 自动化更新链路会腐蚀人工治理成果 | 后台整合任务重建记忆标签数组，把人工治理打的状态标全部洗掉（治理打标被侵蚀的真实事故） |
| 配置驱动、环境档案 | 同一命令在不同 shell / 编码 / 路径约定下行为完全不同（编码炸变量赋值、路径转换报错、代理不生效），靠模型自觉适配必然踩坑（实测） |
| 单一启动入口 | 自愈看门狗绕过正常启动链直接拉进程，丢关键环境变量、抢端口，与正常启动链互踩；自愈机制本身成了故障源（实测） |
| 口头完工无效、验证必须闭环 | 治理类操作"内存对账"不可信，必须重查真实存储（数据库重查）；审查结论必须交独立执行体复核才敢信（实测） |
| 执行体上下文会污染，危险操作必须隔离执行 | 实测发生过：主对话上下文被污染后执行破坏性操作会失控，实践中已固化为：派干净上下文的独立执行体做，主脑只出任务书、收工独立对账 |
| 上下文前缀缓存既是成本杠杆也是脆弱点 | 缓存按前缀匹配，前缀中任一字节变化都会使其后全部失效；实测出现过"一步里换了工具集"导致长会话缓存命中率从高位骤降到低位的事故 |
| 上下文压缩会丢掉长尾约束 | 实测事故：压缩历史时把"改某类文件必须同步两个变更日志"这条纪律当作"已解决的上下文"丢弃，后续再未提起并出错 |
| 不同上下文的并行执行体不共享所学 | 主流隔离式执行体实现均为独立上下文、只回摘要；多方观察到并行执行体各自探索、重复踩坑、经验互不相通（方向性结论 + 官方文档表述） |
| 同一套权重在不同"纪律"下表现不同 | 收紧工具集、调整决策阈值、切换认知姿态提示，比"让模型扮演另一个角色"更能压住运行时退化；能力上限相同、下限不同（方向性结论） |
| 生命周期钩子是真实的攻击面 | 钩子把命令绑定到运行时事件并以宿主权限执行；供应链威胁模型下，攻击者只需控制插件元数据与钩子配置，就能把良性插件变成恶意（第三方安全分析，未独立复核） |

## B. 被现实修正的概念

1. **双终端界面 → 观察面/工作面分离是本质，终端形态是可插拔的**
   早期稿把"双 TUI"当核心交付物，形态锁死。现实中终端交互形态一年内已换过一轮（TUI 弃用回 CLI）。正确抽象：单一事实源 + 观察面与工作面物理分离 + 前端可插拔（CLI 优先，图形/移动端只是可选消费者）。

2. **"像 X 一样低成本" → 零现金、纯 token 预算**
   现实成本约束是自有免费额度，不是选便宜供应商。成本工程的目标函数 = 预算硬控 + 缓存命中 + 任务分级路由 + 记账闭环，全部围绕 token，不围绕钱。选型对比必须基于官方价格信息，免费证据优先，禁烧额度做对照测试。

3. **上下文工程：矛盾有现实解，但必须假设"上下文随时会丢"**
   - "增量演化 vs 缓存稳定"的矛盾有已验证的工程解：运行时元数据从静态前缀剥离、动态内容只注入消息区，缓存命中率可稳定拉满。
   - 但压缩是有损的：实测发生过压缩把重要技能内容裁成占位符、关键上下文蒸发。所以新增公理：关键状态一律外置持久层，产物落盘，结论可复查，绝不把唯一副本放在上下文里。

4. **自我进化/自愈 → 必须限次、熔断、可中断**
   实证事故：自愈机制层层升级（自愈 → shim → 整轮接管）形成更新死循环；配置改动不热生效（落盘后进程仍用旧值运行，还产出过"已生效"的错误结论）。修正为：进化 = 提议 → 评估 → 确认 → 落盘 → 显式生效；自愈只允许有限次数 + 熔断 + 全程留痕，任何"接管行为"必须可被人一键中断。

5. **小模型探针 → 分层落地顺序反转**
   早期稿想直接上小分类器。现实顺序：零成本确定性层（哈希 / 规则 / 查表）先行立住 → 轻量分类器按实测收益再上 → 决策不再交给大模型。决策前置的每一层都必须先证明比上一层多赚到东西。

6. **"规则 vs 小模型"二选一 → 多信号融合**
   单一指标都不可靠。探针必须是多信号融合：确定性哈希（重复调用/死循环）+ 零模型的结构性目标偏离检测 + 轻量分类（风险、档位、领域）。同时**决策链上不引入大模型**——决策一旦依赖模型自觉，一点幻觉就是致命错误（用户定案）。

7. **上下文"裁剪" → 增量累积精炼**
   早期设想"动态裁剪无关上下文省 token"。现实反例：逐轮重写或被激进简化，会产生"简洁偏见"（来之不易的领域细节被压成通用短句）与"上下文崩溃"（逐轮重写导致信息崩塌）。修正为：上下文条目化、增量累积并精炼，只做低成本小增量更新。

8. **网关只是状态存储 → 治理感知的控制平面**
   生命周期钩子以宿主权限执行、可被插件元数据劫持。网关必须统一治理与审计钩子，出站内容经脱敏订阅者过滤，并承担"单一调度入口"职责，否则同一动作会冒出多个互相看不见、判断互相冲突的观察者。

9. **"多个执行体各自学习" → 经验必须共享**
   隔离上下文的执行体各自探索、经验互不相通，越用越蠢。需要共享痕迹层（写入结构化痕迹、下游读取采纳）+ 跨会话记忆引擎兜住"不共享所学"。

10. **"记忆系统能顺带兜住缓存与注意力" → 三件正交、互不替代**
   记忆引擎只解决"跨时间不失忆、经验能共享"；单轮注意力漂移靠认知纪律域；物理拦截靠白名单与调度入口。记忆自身还带三项生产开销（写入纪律、与提示缓存的冲突、跨模型适配）——它是税不是红利，且不负责前缀稳定性。

11. **切换纪律/工具集的代价 → 从"改前缀"改为"追加锚点"**
   早期把"切域要换提示词和工具集"当成免费动作。物理规律是：改前缀即毁缓存。修正为：冻结基础前缀 + 追加式域快照（旧快照退役不重写）+ 白名单收紧移到拦截层——能力目录留在缓存里，运行纪律移到拦截层。

## C. 被推翻 / 降级的概念

- **"半个 AGI"话术**：弃，不进任何文档（无实证支撑的自嗨表述）。
- **记忆"多全熟清"中的"全"**：推翻。实测证明全量记忆是污染源，改为宁缺毋滥 + 硬预算截断。
- **记忆"熟"（主动反思/召回）**：降级为异步限量。反思服务实测有墙钟与 token 预算上限，同步反思会拖死主循环；反思响应不持久化、刷新即失——一次性产物必须落盘存档。
- **全量同步事件审计**：降级为分级。只读异步放行、写入记录、高危同步阻塞，单人单机场景不需要事件风暴级的全同步审计。
- **复杂多 Agent 星座默认化**：降级。多执行体只在任务边界清晰且需要上下文隔离时使用（且必须有明确交接协议和最终裁决者），默认单执行体 + 强状态机。
- **"让大模型做路由与风控决策"**：推翻（用户定案）。决策链改为"探针贴标签 + 配置查表 + 代码裁决"；大模型只输出生成物与标签。
- **"探针保留大模型评估层兜底"**：退出决策链。异常只上报人、或转人工确认，不由大模型自行裁决。
- **一切绝对数值型结论**：降级为方向性参考。第三方自述的命中率、召回率、成本降幅、模型体积、单任务成本等，只用于说明方向，不作设计依据、不写入概念文档。

## D. 对外部参考材料的核验状态

早期调研中出现过的第三方项目名与论文名，一律不进入纯净文档（去工具指向性纪律），本文件同样不点名。其"原理性结论"已抽象后吸收进概念体系：
- 风险分级与前置审批门（拦截与评估物理分离）→ 感知探针 + 分级处置
- 工具调用哈希检测死循环 → 探针确定性层
- 目标条件下的漂移检测 / 证据增量度量 → 状态机熔断条件
- 记忆四杠杆生命周期（重要性/合并/衰减/驱逐）→ 记忆系统纪律
- 缓存稳定前缀工程 → 上下文与成本工程
- 自修改三层防护（代码级范围界定 + 离线评估门 + 人在回路）→ 硬约束 3

第二轮核验（续接对话）状态：
- **可确认存在（第三方来源）**：本地轻量分类路由；规范化生命周期钩子事件总线（含一票否决合并、同步/异步双模、出站脱敏）；纯函数状态机内核（可检查/确定/可重放）；目标条件漂移检测与轨迹护栏；增量式上下文演化；记忆的保留/召回/反思三操作与四路并行检索；置信度衰减与 TTL；代码级自我修改范围界定。
- **可确认存在（决策模型品类，第三轮补核）**：只输出类型化判定与概率（是非 / 选项 / 量表）、不生成文本的专用小型决策模型，有开源可本地运行的实现（校准概率输出、内置升级人工的决策头）；其"置信度管升级、不对越权"的使用模式与本设计"低置信升级人工、不可逆操作由代码兜底"一致。厂商自报的校准质量与准确率为第三方自述，未独立复核。
- **无法确认 / 证据不足**：用户自述的个别小众仓库无法定位到对应实现，标"待核验"；多项"性能领先""命中率极高"为厂商或团队自报，未独立复核；多份第三方"已联网核验"结论未附原始出处，无法二次复核。
- **未核验条目（不作为设计依据）**：漂移检测与死循环检测的具体算法参数、置信度衰减的具体参数、压缩比例、缓存命中率与成本降幅等一切绝对数值。
- **结论性判断**：本轮可核验的外部方案都是**单点能力供给**（路由、记忆、上下文、监控、桌面自动化各占一角），没有与本设计同构的完整底座；这也构成"不 fork、自己手搓"的实证理由——本设计的核心特性（纪律域切换、探针三作用点、单一调度入口、前缀冻结）全部位于内核层，依赖他人内核会被上游版本与钩子点绑架。
