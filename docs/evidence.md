# 实证对账（内部参考）

> 用途：记录 concept-v2 各概念背后的真实运行证据，是设计依据的证据链。
> 可见性：内部。禁止外发，禁止作为代码生成的直接依据（避免工具指向性污染纯净文档）。
> 方法：早期概念稿（空记忆环境纯推演）的每条概念，用真实运行证据过堂，分三类处置。

---

## A. 被实证证实的概念（保留并强化）

| 概念 | 真实运行证据 |
|---|---|
| 记忆必须防污染，不能全存全收 | 真实记忆库 1000+ 条，抽样 40 条仅约 20% 有用：过程垃圾 37%、过期旧结论 37%、重复 11%。垃圾被召回进上下文，是"对话降智"的直接原因 |
| 写入要有证据链/置信度，过期必须衰减 | 已废弃的旧架构设计长期被当作世界事实召回，持续污染决策——过期结论不衰减等于慢性中毒 |
| 自动化更新链路会腐蚀人工治理成果 | 后台整合任务重建记忆标签数组，把人工治理打的状态标全部洗掉（治理打标被侵蚀的真实事故） |
| 配置驱动、环境档案 | 同一命令在不同 shell / 编码 / 路径约定下行为完全不同（编码炸变量赋值、路径转换报错、代理不生效），靠模型自觉适配必然踩坑 |
| 单一启动入口 | 自愈看门狗绕过正常启动链直接拉进程，丢关键环境变量、抢端口，与正常启动链互踩；自愈机制本身成了故障源 |
| 口头完工无效、验证必须闭环 | 治理类操作"内存对账"不可信，必须重查真实存储（数据库重查）；审查结论必须交独立执行体复核才敢信 |
| 执行体上下文会污染，危险操作必须隔离执行 | 主对话上下文被污染后执行破坏性操作会"乱来"（用户原话："你的上下文有污染会乱来，让子代理来安全点"），实践中已固化为：派干净上下文的独立执行体做，主脑只写任务书、收工独立对账 |

## B. 被现实修正的概念

1. **双终端界面 → 观察面/工作面分离是本质，终端形态是可插拔的**
   早期稿把"双 TUI"当核心交付物，形态锁死。现实中终端交互形态一年内已换过一轮（TUI 弃用回 CLI）。正确抽象：单一事实源 + 观察面与工作面物理分离 + 前端可插拔（CLI 优先，图形/移动端只是可选消费者）。

2. **"像 X 一样低成本" → 零现金、纯 token 预算**
   现实成本约束是自有免费额度（小米 token plan），不是选便宜供应商。成本工程的目标函数 = 预算硬控 + 缓存命中 + 任务分级路由 + 记账闭环，全部围绕 token，不围绕钱。选型对比必须基于官方价格页，免费证据优先，禁烧额度做对照测试。

3. **上下文工程：矛盾有现实解，但必须假设"上下文随时会丢"**
   - "增量演化 vs 缓存稳定"的矛盾有已验证的工程解：运行时元数据从静态前缀剥离、动态内容只注入消息区，缓存命中率可稳定拉满。
   - 但压缩是有损的：实测发生过压缩把重要技能内容裁成占位符、关键上下文蒸发。所以新增公理：关键状态一律外置持久层，产物落盘，结论可复查，绝不把唯一副本放在上下文里。

4. **自我进化/自愈 → 必须限次、熔断、可中断**
   实证事故：自愈机制层层升级（自愈 → shim → 整轮接管）形成更新死循环；配置改动不热生效（落盘后进程仍用旧值运行，还产出过"已生效"的错误结论）。修正为：进化 = 提议 → 评估 → 确认 → 落盘 → 显式生效；自愈只允许有限次数 + 熔断 + 全程留痕，任何"接管行为"必须可被人一键中断。

5. **小模型探针 → 分层落地顺序反转**
   早期稿想直接上小分类器。现实顺序：零成本确定性层（哈希 / 规则 / 查表）先行立住 → 轻量分类器按实测收益再上 → LLM 评估只做异常时的兜底。决策前置的每一层都必须先证明比上一层多赚到东西。

## C. 被推翻 / 降级的概念

- **"半个 AGI"话术**：弃，不进任何文档（无实证支撑的自嗨表述）。
- **记忆"多全熟清"中的"全"**：推翻。实测证明全量记忆是污染源，改为宁缺毋滥 + 硬预算截断。
- **记忆"熟"（主动反思/召回）**：降级为异步限量。反思服务实测有墙钟与 token 预算上限（服务端 300s 墙钟 + 10 万 token 预算），同步反思会拖死主循环；反思响应不持久化、刷新即失——一次性产物必须落盘存档。
- **全量同步事件审计**：降级为分级。只读异步放行、写入记录、高危同步阻塞，单人单机场景不需要事件风暴级的全同步审计。
- **复杂多 Agent 星座默认化**：降级。多执行体只在任务边界清晰且需要上下文隔离时使用（且必须有明确交接协议和最终裁决者），默认单执行体 + 强状态机。

- 记忆四杠杆生命周期（重要性/合并/衰减/驱逐）→ 记忆系统纪律
- 缓存稳定前缀工程 → 成本思想第 5 条
